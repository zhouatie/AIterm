## Context

二维码工具的固定常驻链接已经使用 renderer `localStorage` 保存，并在工具内分开展示固定项和最近生成记录。当前列表项右侧存在 icon-only 取消固定入口，但主操作在当前文本已固定时仍然显示“固定”，点击后只更新时间，不会取消固定，用户容易认为固定状态无法撤销。

现有规格已经要求取消固定不清空当前输入，也不删除同文本最近生成记录。本次修复应保持这些持久化和记录语义，只改正当前文本固定状态下的主操作行为。

## Goals / Non-Goals

**Goals:**

- 当前二维码文本已固定时，主操作明确切换为取消固定。
- 取消固定当前文本后，固定列表、React 状态和 `localStorage` 同步更新。
- 列表内取消固定入口继续可用。
- 保持二维码生成、最近记录、复制 SVG 和固定去重行为不变。

**Non-Goals:**

- 不重做二维码工具布局。
- 不新增固定项分组、搜索、批量管理或确认弹窗。
- 不改变 `localStorage` 数据版本或迁移格式。

## Decisions

### 1. 主固定按钮按当前文本切换行为

选择：当当前二维码文本尚未固定时，主按钮继续执行固定；当当前文本已固定时，主按钮执行取消固定，并在 label / tooltip 上体现取消固定语义。

理由：用户固定当前文本后，最直接的撤销路径应保留在同一个操作位置。相比只依赖列表中的 icon-only 入口，切换主按钮更符合当前上下文，也减少用户必须在列表中寻找对应文本的成本。

替代方案：保留主按钮只更新时间，仅改善列表按钮样式。否决原因是用户反馈的失败点发生在“固定之后”的当前上下文，单纯强化列表按钮不能解决主操作不可撤销的感知。

### 2. 取消固定按文本匹配

选择：新增按文本取消固定的逻辑，主按钮使用当前输入文本移除固定项；列表按钮仍可按记录 ID 移除单条固定项。

理由：固定项按文本去重，当前输入只天然持有文本，不应为了取消固定额外查找或暴露记录 ID。按文本移除与固定去重规则一致，也能避免未来记录 ID 重建时影响主操作取消固定。

替代方案：主按钮先查找当前文本对应 ID，再复用按 ID 删除。否决原因是这个路径多一步状态派生，收益不明显，并且按文本才是当前固定语义的唯一稳定键。

## Risks / Trade-offs

- [Risk] 主按钮文案变化可能让“更新时间”入口消失。→ Mitigation：重复固定只用于更新同文本更新时间，用户更需要的是撤销固定；未固定状态仍保留固定入口。
- [Risk] 当前输入有首尾空白时，按文本精确匹配可能无法取消近似内容。→ Mitigation：现有固定、最近记录和二维码生成均按原始输入文本处理，本次保持一致，不引入隐式 trim。
