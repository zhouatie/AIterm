## Context

当前 `MarkdownPreview` 通过 `react-markdown`、`remark-gfm` 和 `rehype-highlight` 渲染 Markdown 内容，并已经对 `pre` 做了自定义包装以提供代码块复制控件。项目中已有 `mermaid` 前端依赖，`UtilityToolsPanel` 已在 renderer 中使用它渲染 SVG，并根据 `ThemeContext` 选择 Mermaid 主题。

这次需求改变 Markdown 预览中的 `mermaid` fenced code block 展示方式，并让 Markdown 预览和 Mermaid 工具中的 Mermaid 图表共享全屏查看与滚轮缩放体验。不改变文件读取、任务 checkbox 写回、评论、查找、标题导航或普通代码块行为。

## Goals / Non-Goals

**Goals:**
- 在 Markdown 预览中识别 fenced code block 的 `language-mermaid` 标识。
- 使用现有 `mermaid` 依赖在 renderer 端把 Mermaid 源码渲染为 SVG。
- 根据当前 light/dark 主题选择 Mermaid 渲染主题。
- Mermaid 渲染失败时展示错误状态，并保留源码可读。
- 滚动预览、评论标记定位等视口状态变化不触发 Markdown 正文和 Mermaid 图表重复渲染。
- Markdown 预览和 Mermaid 工具中的 Mermaid 图表支持点击全屏查看。
- 全屏查看层支持鼠标滚轮放大和缩小，并限制缩放范围。
- 全屏查看层支持图表模式和源码模式切换，用于查看复杂 Mermaid 源码（包括时序图源码）。
- 全屏打开时按 SVG intrinsic 尺寸和可用画布尺寸计算初始缩放比例，使图表默认等比撑满查看区域。
- 全屏打开时优先使用 SVG 可见内容边界进行适配，避免 Mermaid SVG 声明画布含大量空白时图表显示过小。
- 全屏查看层中的图表 / 源码切换控件点击命中区域与视觉按钮边界一致，避免实际点击位置向下偏移。
- 全屏查看层右上角工具栏中的图表、源码、复制、关闭四个控件完整可见区域都可点击。
- 全屏查看层提供模式感知的一键复制：图表模式复制当前 SVG，源码模式复制 Mermaid 源码。
- 全屏查看层中的缩放百分比固定在全屏容器右下角，关闭按钮保持在右上角。

**Non-Goals:**
- 不新增 Markdown 编辑能力。
- 不为 Mermaid 图表增加交互编辑、导出或历史记录。
- 不实现图表拖拽平移、缩略图导航或持久化缩放比例。
- 不在源码模式中提供编辑或保存能力；源码模式只用于查看和复制。
- 不改变普通 fenced code block 的高亮和复制行为。
- 不引入新的渲染服务或后端 IPC。

## Decisions

1. 在 `MarkdownPreview` 中新增专用 Mermaid 代码块组件。
   - 原因：需求只影响 Markdown 预览，放在当前组件内可以复用已有 `pre` 自定义入口，并保持改动范围集中。
   - 替代方案：通过 remark/rehype 插件转换 AST。该方案会增加渲染链路复杂度，也不便于处理异步 Mermaid 渲染状态。

2. 通过 `pre` 子节点中的 `code` className 判断 `language-mermaid`。
   - 原因：这是 `react-markdown` 现有渲染链路中最接近当前代码块包装的位置，能继续让非 Mermaid 代码块走原来的复制组件。
   - 替代方案：覆盖 `code` component。当前复制按钮绑定在 `pre` 层，直接覆盖 `code` 会把普通代码块和 inline code 的处理混在一起。

3. 每个 Mermaid 代码块组件独立维护渲染状态，并使用稳定递增 id 调用 `mermaid.render`。
   - 原因：同一 Markdown 文件可能包含多个 Mermaid 图表，独立状态可以避免某个图表失败影响其它图表；唯一 id 避免 Mermaid 内部 SVG id 冲突。
   - 替代方案：在父组件集中收集并批量渲染。该方案需要额外索引和 DOM 协调，和现有 `react-markdown` 组件化渲染方式不一致。

4. 保持 Mermaid `securityLevel: 'strict'`。
   - 原因：与现有工具面板一致，Markdown 文件内容来自工作区文件，不应放宽 SVG 注入安全策略。

5. 将 Markdown 正文渲染与滚动驱动的覆盖层状态隔离。
   - 原因：当前预览滚动会更新评论定位相关状态，如果 `ReactMarkdown` 跟随父组件一起重渲染，会让 Mermaid 图表反复进入 loading 或重新调用渲染。Markdown 正文应封装为只依赖内容、任务上下文和操作回调的 memoized 子组件，滚动状态只更新评论 marker/selection toolbar 等覆盖层。
   - 替代方案：移除滚动中的评论定位刷新。该方案会降低评论标记在滚动或横向滚动场景下的定位可靠性。

6. 提供共享的 Mermaid 图表查看组件，供 Markdown 预览和 Mermaid 工具复用。
   - 原因：两处展示的输入都是已渲染 Mermaid SVG，需要一致的全屏打开、关闭、滚轮缩放、缩放范围和基础样式。共享组件可以避免两套状态逻辑不一致。
   - 替代方案：分别在 `MarkdownPreview` 和 `UtilityToolsPanel` 内实现全屏查看。该方案会重复 SVG 注入和缩放逻辑，后续行为容易分叉。

7. 全屏查看层使用应用内 modal 覆盖层而不是浏览器 Fullscreen API。
   - 原因：应用内 modal 能保持 Electron 窗口内交互一致，也不需要额外权限或处理系统全屏状态。滚轮事件可在查看层内局部处理。
   - 替代方案：调用 Fullscreen API。该方案会改变系统级窗口状态，退出/焦点行为复杂，且与现有工具面板 overlay 模式不一致。

8. 全屏查看组件接收 Mermaid 源码，并在全屏工具栏提供图表 / 源码分段切换。
   - 原因：Markdown 预览和 Mermaid 工具都能持有 Mermaid 源码，直接传入共享组件即可避免从 SVG 反推源码。源码模式只读展示，图表模式继续承担缩放交互。
   - 替代方案：只在 Mermaid 工具中支持源码切换。该方案会让 Markdown 中的时序图缺少同等排查能力。

9. 全屏图表初始缩放使用 fit-to-canvas 策略。
   - 原因：Mermaid 图表尺寸差异很大，固定 100% 会导致复杂时序图打开后过小或超出视口。打开全屏时读取 SVG 的 `viewBox`、`width/height` 或 DOM bbox 尺寸，并与画布可用宽高计算等比缩放，默认填满但不变形。
   - 替代方案：CSS `max-width: 100%; max-height: 100%`。该方案无法与后续滚轮缩放使用同一个 zoom 状态统一表达，也不利于显示当前缩放百分比。

10. 全屏工具栏中的图表 / 源码切换使用固定高度的分段按钮。
   - 原因：切换控件需要让视觉按钮和 pointer hit target 对齐，并保持在图表画布之上。显式设置按钮高度、box sizing、对齐方式和工具栏层级，可以避免点击命中区域向下偏移或被画布覆盖。
   - 替代方案：复用普通文本按钮默认样式。该方案会受全局 line-height、padding 或 overlay 层级影响，难以保证命中区域稳定。

11. 全屏复制按钮根据当前模式选择复制内容。
   - 原因：图表模式用户通常需要复制已渲染 SVG，源码模式用户需要复制 Mermaid 源码；放在同一工具栏中可避免在图表和源码区域内各自增加重复控件。
   - 替代方案：只复制 Mermaid 源码。该方案无法满足图表模式下直接复用 SVG 的需求。

12. 全屏图表缩放后的布局尺寸与缩放状态保持一致。
   - 原因：如果只使用 CSS transform 缩放，元素布局尺寸不会随视觉尺寸变化，可能导致默认 fit 后看起来没有占满容器。共享组件应基于 SVG intrinsic 尺寸和 zoom 同步设置图表容器的实际宽高，同时保持宽高比。
   - 替代方案：继续只使用 transform 缩放。该方案实现简单，但默认占满和滚动范围都容易与视觉结果不一致。

13. 全屏缩放百分比脱离工具栏并固定在容器右下角展示。
   - 原因：缩放百分比属于图表画布状态，放在工具栏会挤占右侧操作区，并在模式切换或显示隐藏时影响按钮布局。将其作为全屏容器内的固定定位状态标记，可以避免推动图表 / 源码切换、复制和关闭按钮，同时保持关闭按钮在右上角。
   - 替代方案：继续放在工具栏右侧固定槽位。该方案能稳定按钮位置，但会让工具栏右侧布局拥挤，不符合当前交互调整。

14. 全屏图表适配优先基于 SVG 可见内容 bbox。
   - 原因：Mermaid 生成的 SVG 可能存在比实际图形大很多的 viewBox 或空白画布，直接用声明尺寸计算 fit zoom 会让可见图形在全屏容器中显得过小。全屏模式应读取 SVG `getBBox()` 得到可见内容边界，带少量安全 padding 后临时归一化全屏 SVG 的 viewBox，再基于该可见边界计算初始缩放。
   - 替代方案：继续使用 SVG `viewBox` / `width` / `height` 作为唯一尺寸来源。该方案对空白画布敏感，会复现图表在大容器里只占很小一块的问题。

15. 全屏右上角工具栏控件使用完整按钮命中盒。
   - 原因：图表、源码、复制、关闭是全屏层的主要操作入口，用户会点击按钮背景、图标边缘、文字边缘或中心。四个控件都应让完整可见按钮区域接收 pointer 事件，并避免图标 SVG、伪元素或相邻 overlay 抢占命中。
   - 替代方案：仅保证文字或图标中心可点击。该方案不符合用户对可见按钮区域的预期，也会继续表现为“必须点偏一点才触发”。

## Risks / Trade-offs

- Mermaid 渲染是异步的，内容或主题快速变化可能产生过期结果 → 每次渲染使用组件内版本号，只接受最新结果。
- Mermaid 源码解析失败会导致该图表无法展示 → 在图表位置显示错误信息和源码，用户可以直接定位问题。
- Mermaid SVG 可能比预览宽度更宽 → 外层容器提供横向滚动，避免撑破 Markdown 预览布局。
- Markdown 正文 memoization 可能遗漏必要依赖 → 子组件 props 必须覆盖内容、任务上下文、checkbox/apply 回调和禁用状态；主题变化由 Mermaid 图表组件直接读取 `ThemeContext`。
- 全屏查看层中的滚轮缩放可能与页面滚动冲突 → 查看层内拦截 wheel 事件并只改变图表缩放比例，关闭查看层后恢复原页面滚动行为。
- SVG 注入仍使用 `dangerouslySetInnerHTML` → 仅注入本地 `mermaid` 依赖在 strict 安全配置下生成的 SVG，不直接注入用户原始源码。
- 初始 fit zoom 依赖 SVG 尺寸可读取 → 优先使用 SVG `viewBox` / `width` / `height`，必要时回退到 DOM bbox；无法读取时回退到 100%。
- SVG 可见内容 bbox 可能不包含描边、箭头或文字边缘 → 归一化 viewBox 时加入少量 padding，避免裁剪边缘内容；无法读取 bbox 时回退到声明尺寸。
- 源码模式下不响应滚轮缩放 → 滚轮缩放仅作用于图表模式，源码区域保留常规滚动阅读。
- 全屏模式切换控件可能受全局按钮样式影响 → 分段按钮显式定义高度、line-height、box-sizing 和层级，避免命中区域与视觉区域错位。
- Clipboard API 可能因运行环境或权限失败 → 复制操作需要捕获失败并在工具栏中给出短暂反馈，不改变当前全屏模式或关闭查看层。
- 最大缩放比例可能限制极小图表继续放大 → 仍以等比适配和可控缩放上限为准，避免初始打开后图表无限放大影响可读性。
- 缩放百分比在源码模式下没有实际含义 → 仅在图表模式显示右下角状态标记，源码模式隐藏该标记且不影响工具栏布局。
- 全屏右上角工具栏控件彼此间距较近 → 每个控件使用独立稳定盒模型，SVG 图标禁用 pointer-events，工具栏保持在画布层级之上，避免相邻元素或画布抢占点击。
