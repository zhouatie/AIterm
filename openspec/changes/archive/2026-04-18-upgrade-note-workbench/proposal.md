## Why

当前笔记模块虽然已经具备基础的文件读写与 Markdown 编辑能力，但整体仍更像“附属文件编辑器”，而不是一个高频可用的笔记产品。现有多 Tab + 树形文件列表的交互路径偏重文件管理，缺少最近访问、收藏、目录内浏览、明确保存状态与上下文恢复等关键能力，导致记录和回看笔记时频繁打断主工作流。

在保留 overlay 形态的前提下，需要把笔记模块升级为一个轻量但完整的全局笔记工作台，让用户在不引入复杂知识管理能力的情况下，也能获得稳定、顺手、视觉更优雅的日常笔记体验。

## What Changes

- 保留笔记模块作为 overlay 的入口形态，但重做 overlay 内部布局与视觉表现，使其成为专注型笔记工作台，而不是简单覆盖式工具面板。
- 将当前“文件树 + 多 Tab 编辑器”的主交互改为“icon 视图栏 + 合并导航树 + 单文档编辑区”的结构。
- 移除多标签页编辑模型，改为单文档编辑流；打开笔记时直接切换当前文档，并恢复上次目录、文档与编辑上下文。
- 保留强文件夹层级入口，支持通过单一导航树同时完成视图切换结果浏览与目录定位，避免分离的文件夹树与笔记列表继续占用横向空间。
- 增加 `最近`、`收藏`、`全部` 视图，补齐轻量高质基础版笔记应有的导航能力。
- 提升编辑反馈与安全性，增加可见的自动保存状态，并优化新建、重命名、删除等高频操作的交互细节。

## Capabilities

### New Capabilities
- `note-navigation`: 定义全局笔记工作台中的最近、收藏、全部视图，目录定位后的笔记列表，以及上次笔记上下文恢复行为。

### Modified Capabilities
- `note-panel`: 将现有 overlay 笔记面板从多 Tab 文件编辑器升级为单文档笔记工作台，并重构其布局、导航与高频操作交互。
- `note-autosave`: 在现有自动保存能力基础上增加可见保存状态反馈，匹配单文档编辑流中的“编辑中 / 保存中 / 已保存”体验。

## Impact

- 受影响前端模块主要包括 `src/components/NotePanel.tsx`、`src/components/NoteFileList.tsx`、`src/components/NoteEditor.tsx` 及其相关状态管理。
- 受影响工具层包括 `src/utils/note-autosave.ts` 与笔记相关的本地持久化设置逻辑。
- 可能需要新增用于最近、收藏与上下文恢复的前端状态持久化结构，但不引入新的外部依赖。
- 现有 `note-panel` 与 `note-autosave` spec 需要更新，并新增 `note-navigation` spec 作为工作台级导航能力的契约。
