## Context

当前笔记模块仍建立在“单个 `noteDir` + `最近/收藏/全部` 视图 + 单一导航树”的状态模型上。这个模型已经能支持基础读写，但它把导航模式、树节点交互和目录配置耦合到了一起：左侧既要承担视图切换，又要承担文件树定位；文件夹单击同时承担选中和展开；设置面板里也只有一个笔记目录输入框，无法承载多个 Obsidian Vault 的切换需求。

这次变更的外部约束已经明确：

- 笔记模块继续保持 overlay 形态，不改成常驻主面板。
- 应用内一次只激活一个当前 Vault，不同时显示多个 Vault 文件树。
- 文件夹单击只负责选中，展开/收起仅由箭头触发。
- `最近` / `收藏` 不再作为笔记导航模式存在。
- 当前没有可直接消费的 Figma 节点，本次视觉方案只能基于现有工作台语言与 Obsidian 文件浏览器交互心智收敛。

## Goals / Non-Goals

**Goals:**

- 将笔记模块重构为“当前 Vault 切换器 + 当前 Vault 文件树 + 单文档编辑区”的单一 Vault Explorer。
- 用可持久化的 Vault 列表和当前激活 Vault 替换现有单 `noteDir` 配置。
- 移除 `activeView`、`recent`、`favorites` 这类视图型导航状态，让笔记导航重新回到单树模型。
- 让当前 Vault、当前文件夹、当前文档的恢复逻辑按 Vault 维度隔离，避免跨 Vault 状态串扰。
- 将笔记树交互收敛为更接近 Obsidian 文件浏览器的语法，并补齐最小右键菜单。
- 让文件与文件夹的重命名都只通过显式入口触发，不再依赖双击。
- 支持在当前 Vault 内通过拖拽把文件或文件夹移动到其他文件夹下，同时保持当前文档与上下文路径同步。

**Non-Goals:**

- 不支持同时并列展示多个 Vault 的文件树。
- 不引入全文索引、标签、双链、模板、知识图谱等笔记增强能力。
- 不实现跨 Vault 文件移动或同层级手动排序。
- 不保留 `最近` / `收藏` 的兼容 UI。

## Decisions

### 1. 用 Vault 注册表替换单一 `noteDir`

笔记存储配置从单个路径升级为 Vault 注册表，至少包含：

- `vaults`: 已保存 Vault 列表，每项包含稳定 `id`、显示名 `name`、根路径 `rootPath`
- `activeVaultId`: 当前激活 Vault

默认情况下，系统仍以 `{userData}/notes` 作为初始默认 Vault；若用户此前已经保存过旧的单 `noteDir`，则在首次读取新模型时把该路径迁移成一个 Vault 条目。

选择这个方案的原因：

- 用户已经明确要“在应用里切换当前 Vault”，单路径模型无法继续演进。
- 把显示名和路径拆开，可以避免 UI 被绝对路径挤占，同时保留稳定引用。
- 在存储层就引入 `activeVaultId`，比在 NotePanel 内临时推导当前 Vault 更清晰。

备选方案：

- 继续只保存多个路径数组，不引入 `activeVaultId`：切换当前 Vault 时仍需要额外状态源，模型不完整。
- 直接把 Vault 列表塞进 workbench state：会把“存储配置”和“会话上下文”混在一起，职责不清。

### 2. 工作台上下文按 Vault 维度隔离持久化

现有 `NoteWorkbenchState` 中的 `activeView`、`recent`、`favorites` 直接移除，只保留单树浏览真正需要的上下文：

- 当前激活 Vault
- 每个 Vault 自己的 `selectedFolderPath`
- 每个 Vault 自己的 `currentNotePath`

恢复逻辑也按 Vault 维度执行：切换到某个 Vault 时，只恢复该 Vault 上次的当前文件夹与当前文档；若路径失效，则回退到该 Vault 根目录或空文档状态。

选择这个方案的原因：

- 用户已经明确不需要 `最近` / `收藏`，继续保留只会给状态迁移制造负担。
- 目录路径和文件路径天然依赖 Vault 根目录，跨 Vault 共用一套上下文会产生串路径问题。
- 这样可以让“切换 Vault”和“重新打开笔记面板”的恢复逻辑复用同一套状态模型。

备选方案：

- 只记录一个全局 `selectedFolderPath/currentNotePath`：切到另一个 Vault 时容易引用到无效路径。
- 每次切换 Vault 都重置为空状态：实现简单，但会丢失用户在各个 Vault 之间来回切换时的上下文连续性。

### 3. 左侧导航收敛为单一 Vault Explorer，而不是模式切换器

笔记面板内部布局改为两段式：

```text
当前 Vault Explorer | 编辑区
```

左侧 Explorer 由顶部控制条和当前 Vault 文件树组成；顶部控制条包含：

- `当前 Vault` 切换器
- 搜索框
- `新建笔记`
- `新建文件夹`
- `更多`

不再保留独立的 icon rail，也不再切换 `最近 / 收藏 / 全部` 模式。

选择这个方案的原因：

- 既然一次只激活一个 Vault，左侧最重要的结构就应该是“当前 Vault 是谁”，而不是“当前视图是哪种模式”。
- 去掉 mode rail 后，左侧可以把更多横向空间留给真实文件树，减少碎片化。
- 这更接近 Obsidian 的核心心智：先确定当前 Vault，再浏览当前 Vault 内的树。

备选方案：

- 保留现有 rail，只把它改成 Vault 列表：会把切换器和导航树拆成两层窄栏，信息密度更差。
- 左侧先列出所有 Vault，再在下方展开当前树：用户已经明确不需要同时显示多个 Vault。

### 4. 文件夹单击只选中，展开/收起只由箭头触发

树节点交互改成：

- 文件夹行单击：只更新当前选中文件夹，不自动展开或收起
- 文件夹箭头点击：展开 / 收起
- 文件点击：打开为当前文档
- 搜索命中时：树保留祖先链路，当前文档自动保持可见

选择这个方案的原因：

- 这是用户明确确认的交互规则。
- 目录选择与结构展开是两种不同意图，合并到同一次单击里会导致误触和状态跳变。
- 该交互更适合在右侧创建笔记、创建文件夹等操作依赖“当前选中文件夹”的模型。

备选方案：

- 单击同时选中并展开：实现沿用成本低，但会持续制造误触。
- 双击展开文件夹：桌面树控件里过于反直觉，也不如箭头可发现。

### 5. 右键菜单只保留笔记文件树的最小操作集

继续沿用当前渲染层自绘 `ContextMenu`，但为笔记树定义独立的最小菜单集合：

- 空白区：`新建笔记`、`新建文件夹`
- 文件夹：`新建笔记`、`新建文件夹`、`重命名`、`删除`、`在 Finder 中显示`
- 文件：`打开`、`重命名`、`删除`、`在 Finder 中显示`

同时移除树节点上的 hover 删除按钮，把危险动作尽量收回到右键菜单中；顶部工具区只保留高频创建动作。

选择这个方案的原因：

- 用户明确要求“右键菜单保留一些基本功能即可”。
- 把删除按钮常驻在树行 hover 区会让导航树更像操作列表，而不是文件浏览器。
- 继续复用自绘菜单可以避免引入系统原生菜单差异。

备选方案：

- 完全保留 hover 操作按钮：实现简单，但不能解决树显得吵的问题。
- 为笔记树单独再写一套菜单组件：会增加视觉与行为漂移。

### 6. 文件与文件夹重命名都只保留显式入口，不再绑定双击

文件与文件夹双击都不再进入重命名模式；两者的重命名都只通过右键菜单或其他明确的“Rename”动作进入。

选择这个方案的原因：

- 用户已明确要求去掉文件与文件夹双击重命名。
- 在当前模型下，文件双击天然会被理解成打开流的一部分，文件夹双击也不该和“单击只选中、箭头负责展开”产生第二套隐藏语义。
- 把重命名收回到显式入口后，文件树的浏览语义会更稳定。

备选方案：

- 保留双击重命名：实现省事，但继续保留误触风险。
- 允许文件夹双击重命名、只去掉文件双击重命名：规则不一致，会继续增加认知负担。

### 7. 文件与文件夹拖拽移动只支持“移动到其他文件夹”

当前 Vault 内的文件节点和文件夹节点都支持拖拽到另一个文件夹节点上，落下后通过已有路径变更能力完成实际移动；不支持跨 Vault 移动，也不支持拖成同级排序。

推荐实现约束：

- 文件节点与文件夹节点都必须可以作为 drag source 被拖起
- 只有文件夹节点可作为 drop target
- 文件夹不得被拖入其自身或任意后代目录
- 若当前正在编辑的文档被移动，编辑器中的 `filePath` 与上下文状态必须同步更新
- 成功移动后刷新树，并保持目标路径可见

选择这个方案的原因：

- 用户明确要求“文件与文件夹支持挪动到其他文件夹里”。
- 该交互可以直接复用现有的路径更新和 `fs:rename` 语义，不需要再引入新的文件系统能力。
- 把范围限制为“移动到文件夹”能显著降低拖拽状态与排序逻辑的复杂度。

备选方案：

- 同时支持同层级排序：更强，但会引入额外的落点计算和展示规则，不符合本轮收敛目标。
- 仅支持文件拖拽，不支持文件夹拖拽：实现更轻，但不满足已确认输入。

### 8. 设置面板改为 Vault 管理入口，而不是单路径输入框

设置面板中的“笔记目录配置”改为“Vault 管理”区，至少支持：

- 展示已保存 Vault 列表
- 新增一个 Vault 路径
- 指定当前激活 Vault

新增时延续现有路径校验思路：要求绝对路径、可访问、且不得与已有 Vault 根路径重复。

选择这个方案的原因：

- 只有在设置面板中形成显式的 Vault 管理入口，顶部切换器才有稳定的数据来源。
- 这可以最大程度复用现有“输入路径并保存”的交互模式，而不是额外开新面板。

备选方案：

- 顶部切换器里直接承担“新增 Vault”输入：会把配置型动作塞进高频导航区，干扰主流程。
- 只允许在设置面板切换，不提供顶部切换器：违背“像 Vault Explorer 一样先切当前 Vault”的目标。

## Risks / Trade-offs

- [旧的 `noteDir`、`activeView`、`favorites`、`recent` 状态迁移不完整] → 启动时先迁移 `noteDir` 到默认 Vault，再忽略无法映射的新旧导航状态，避免半迁移状态继续污染新模型。
- [按 Vault 隔离上下文会增加状态结构复杂度] → 仅保留 `selectedFolderPath/currentNotePath` 两类最小上下文，不把更多 UI 状态一起持久化。
- [去掉 hover 删除按钮后，部分用户会觉得删除入口变深] → 顶部工具区保留创建动作，删除统一放进右键菜单，降低误触优先于缩短一步路径。
- [拖拽移动可能误把节点拖入错误目录] → 将 drop target 限制为明确高亮的文件夹节点，并在非法目标上拒绝落下。
- [拖拽移动后当前文档路径与上下文状态不同步] → 统一复用现有 rename/path replacement 逻辑更新 `currentNotePath`、`selectedFolderPath` 和编辑器状态。
- [当前自绘菜单未必完全覆盖 Obsidian 的细节体验] → 本轮只对齐核心心智和最小功能，不追求一比一复刻。

## Migration Plan

1. 先引入 Vault 注册表读取逻辑，并在首次读取时把旧 `noteDir` 迁移成一个默认 Vault 条目。
2. 重构 NotePanel 与 note workbench state，让 `activeView`、`recent`、`favorites` 退出主流程。
3. 再改左侧 Explorer 布局与树交互，接入当前 Vault 切换器和最小右键菜单。
4. 最后更新设置面板，把单路径输入改为 Vault 管理入口。

回滚时，只需恢复旧的 `noteDir` 读取与旧 NotePanel 布局；已有 Markdown 文件与 Vault 根目录不会被改写。
