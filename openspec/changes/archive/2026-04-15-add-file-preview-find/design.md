## Context

当前文件预览模块由 `FilePreviewPanel` 负责文件选择和布局，右侧根据文件类型分别渲染 `MarkdownPreview` 与 `CodePreview`。左侧文件树已经存在独立搜索框，但右侧预览区没有统一的查找状态、查找 UI 或匹配导航能力；全局快捷键系统也没有“查找当前预览内容”的动作定义。

这次变更横跨文件预览容器、两类预览组件、全局快捷键配置和设置面板，属于典型的跨模块交互增强。目标是在不引入额外兼容层的前提下，为当前选中文件提供接近编辑器 `Command + F` 的查找体验。

## Goals / Non-Goals

**Goals:**

- 支持在文件预览模块中通过 `Command + F` 打开右侧预览区查找框
- 支持对当前 Markdown 预览和代码预览内容执行文本查找
- 支持匹配高亮、结果计数、上一个/下一个结果导航和关闭查找框
- 支持在设置面板中展示并保存该快捷键配置

**Non-Goals:**

- 不实现左侧文件树搜索框的快捷键聚焦
- 不实现正则、大小写敏感、整词匹配等高级搜索模式
- 不实现跨文件搜索或项目级全文搜索
- 不改变现有 Markdown 渲染、代码高亮或文件树过滤的基础行为

## Decisions

### 1. 由 `FilePreviewPanel` 统一持有查找状态

查找框的打开/关闭状态、查询文本、当前匹配索引应由 `FilePreviewPanel` 管理，而不是分散到 `MarkdownPreview` 或 `CodePreview`。

原因：

- 查找框属于右侧预览区级别的交互，不属于单一渲染器私有状态
- 文件切换时需要统一重置或迁移查找状态
- `Command + F` 触发后需要由容器层决定当前目标组件并聚焦输入框

备选方案：

- 让 `MarkdownPreview` / `CodePreview` 各自维护查找状态。该方案会导致快捷键分发、文件切换和 UI 一致性处理重复，因此不采用

### 2. 查找框固定作用于“当前选中文件”的右侧预览内容

查找框只搜索当前正在预览的单个文件，不影响左侧文件树，也不跨文件扩展。

原因：

- 与用户需求“右侧预览区”的语义一致
- 可以直接复用当前已加载的文件文本，不需要新增 IPC 或索引能力
- 可以避免与文件树搜索框形成语义冲突

备选方案：

- 复用左侧文件树搜索框并切换模式。该方案会让一个输入框承载两种搜索语义，交互不清晰，因此不采用

### 3. 匹配计算基于原始文本，渲染层负责高亮和滚动定位

`FilePreviewPanel` 只维护查询词和导航方向；`MarkdownPreview` 与 `CodePreview` 分别根据原始文本生成匹配结果，并负责把当前匹配项滚动到可视区域。

原因：

- 两种预览的 DOM 结构差异大，统一在容器层做匹配定位会丢失渲染上下文
- Markdown 预览可能被拆成多个元素节点；代码预览则按行和 token 输出，分别处理更稳妥
- 组件内部最容易拿到高亮标记和当前匹配元素引用

备选方案：

- 在容器层直接操作 DOM 扫描文本节点。该方案脆弱且难维护，对两种预览实现耦合过高，因此不采用

### 4. 快捷键仍纳入现有应用级可配置体系

新增一个文件预览查找 action，默认绑定为 `Command + F`，通过现有 `ShortcutContext` 注册、校验、持久化，并在设置面板快捷键区展示。

原因：

- 项目已有统一快捷键入口，新增动作应遵守同一模型
- 便于与现有冲突校验、持久化和展示逻辑复用
- 避免把 `Command + F` 写死在局部组件里，破坏全局一致性

备选方案：

- 仅在 `FilePreviewPanel` 本地监听 `keydown`。该方案绕过现有快捷键体系，也无法进入设置面板，因此不采用

### 5. 文件切换时关闭查找框并清空匹配上下文

当用户切换到另一个文件时，查找框关闭，查询文本和当前匹配索引重置。

原因：

- 新文件内容与旧查询通常无关，沿用旧结果会造成误导
- 重置行为简单明确，减少“空结果但输入框还在”的歧义

备选方案：

- 保留查询词并在新文件上继续搜索。该方案也可行，但更适合编辑器型产品；当前预览模块以轻量查看为主，优先选择更确定的重置行为

## Risks / Trade-offs

- [Markdown 高亮需要保持原有渲染结构] → 通过在文本渲染节点上做局部标记，避免破坏 GFM checkbox、代码块等既有行为
- [代码高亮与查找高亮叠加可能影响可读性] → 查找高亮使用独立视觉层级，并确保当前匹配项与普通匹配项有明显区分
- [全局快捷键与输入焦点冲突] → 复用现有 `isEditableTarget` 规则，并在查找框聚焦后允许常规文本输入而不再次触发全局动作
- [大文件查找性能下降] → 初版只基于当前已加载文本做字符串匹配，不引入正则和复杂搜索选项，控制计算复杂度
