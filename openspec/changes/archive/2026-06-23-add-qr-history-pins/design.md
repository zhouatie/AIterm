## Context

`UtilityToolsPanel` 目前在 renderer 内集中管理 JSON、二维码和 Mermaid 工具状态。二维码工具使用 `qrcode` 在输入变化后自动生成 SVG，状态只存在于 React 组件内；关闭面板后同一 renderer 会话可保留，但应用重启后不会恢复。

本次变化只扩展通用二维码工具，不改变 Live View 二维码。用户要保存的是二维码内容文本本身，而不是生成后的 SVG，因此持久化对象应小、可读、可去重，并且不需要主进程参与。

## Goals / Non-Goals

**Goals:**

- 在二维码工具内展示最近 10 次成功生成记录。
- 支持将当前二维码文本固定为常驻链接，并跨应用会话保留。
- 点击最近记录或固定项时回填输入区，并复用现有二维码生成流程。
- 提供删除、清空最近记录、固定和取消固定能力。
- 避免自动生成时把用户输入过程中的半成品写入最近记录。

**Non-Goals:**

- 不改变 Live View 二维码入口和行为。
- 不保存或导出二维码 SVG 文件。
- 不新增云同步、多设备同步或工作区级共享。
- 不为固定项增加复杂分组、搜索、排序或标签管理。

## Decisions

### 1. 使用 renderer `localStorage` 持久化二维码记录

选择：在 renderer 侧使用单一 `localStorage` key 保存最近记录和固定项，例如：

```ts
interface QrToolStorageV1 {
  version: 1;
  recent: QrToolItem[];
  pinned: QrToolItem[];
}

interface QrToolItem {
  id: string;
  text: string;
  createdAt: number;
  updatedAt: number;
}
```

理由：二维码工具是本地轻量工具，数据只服务当前用户和当前应用实例。`localStorage` 已足够承载少量文本记录，避免新增 IPC、文件格式或主进程持久化复杂度。

替代方案：使用主进程文件存储。否决原因是本次数据量小、无需跨 renderer 共享，也不需要文件系统权限或迁移机制。

### 2. 最近记录与固定项分开展示和存储

选择：最近记录最多保存 10 条，固定项单独保存，不计入最近记录上限，也不会被最近记录淘汰。

理由：最近记录表达时间顺序和临时找回，固定项表达用户显式保留。把两者分开可以避免高频临时输入挤掉常驻链接，也避免固定项占用最近 10 条容量。

替代方案：使用一个列表加 `pinned` 字段排序。否决原因是 UI 和裁剪逻辑更容易混淆，特别是“最多 10 条”到底包含不包含固定项会变得不直观。

### 3. 只在成功生成且输入稳定后写入最近记录

选择：二维码 SVG 成功生成后，对当前输入设置短延迟保存；如果延迟期间输入继续变化，则取消旧保存。保存时按文本精确去重，重复内容只更新 `updatedAt` 并移动到最近记录顶部。

理由：当前二维码工具是输入即生成。若每次成功生成都立即写历史，用户输入 URL 的过程中会产生大量半成品记录。稳定延迟可以保留自动记录体验，同时减少历史污染。

替代方案：要求用户点击“保存到最近”。否决原因是“最近 10 次生成记录”更符合自动记录预期；显式操作保留给固定项。

### 4. 固定动作以当前输入文本为来源

选择：二维码工具在当前输入非空且生成成功时提供固定按钮。固定后如果同文本已经存在于固定项，则更新时间并保持单条记录；取消固定只影响固定列表，不清空当前输入，也不删除最近记录。

理由：固定是用户显式选择的“常驻链接”，应以当前可预览二维码内容为准。取消固定不应破坏用户当前工作流。

替代方案：允许从最近列表单独固定。可以作为同一能力的一部分实现，但不是唯一入口；当前输入固定是最低必要路径。

### 5. 在二维码工具内增加紧凑记录区域

选择：保留当前左右分栏：左侧仍以输入为主，在输入区下方或旁侧展示固定项与最近记录；右侧继续展示二维码预览和复制 SVG 操作。窄视口下记录区域应可滚动，不挤压二维码预览到不可用。

理由：记录服务于输入复用，放在输入侧能减少用户视线和鼠标移动；预览侧保持二维码主体和复制 SVG 能力的稳定位置。

替代方案：把历史列表放入独立 tab。否决原因是用户需要在同一个二维码工作流里快速选择、预览和固定，拆成 tab 会增加来回切换。

## Risks / Trade-offs

- [Risk] 二维码内容可能包含敏感 token，本地记录会增加暴露面。→ Mitigation：只本地保存；提供单条删除、清空最近记录和取消固定；不自动上传或写入日志。
- [Risk] 自动记录仍可能保存用户暂停输入时的半成品。→ Mitigation：使用成功生成后的稳定延迟，并允许用户快速删除最近记录。
- [Risk] 固定项过多会挤压输入区域。→ Mitigation：固定项和最近记录使用可滚动列表，单条内容截断并通过 title 展示完整文本。
- [Risk] 旧的或损坏的 `localStorage` 数据导致面板渲染异常。→ Mitigation：加载时做 schema 校验，解析失败时回退为空状态并在下一次保存时覆盖。
