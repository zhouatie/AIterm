## Context

当前笔记工作台的数据模型已经完成第一轮收敛：支持多 Vault、当前 Vault 文件树、单文档编辑以及同 Vault 内的基础拖拽移动。本轮不再改动存储结构或导航架构，而是聚焦文件树的高频微交互，让右键菜单、拖拽入口和反馈层级更接近 Obsidian 文件浏览器的心智。

本次变更存在三个已确认约束：

- `收藏` 仅保留菜单位，不落地任何持久化模型或额外 UI。
- 拖拽入口从独立手柄改为整行可拖，并要求拖动中源节点和目标文件夹都具有明确高亮。
- 文件夹整行点击应当可以直接展开或收起文件夹，不再要求必须点击箭头。
- Vault 根节点不视为普通文件夹，不允许 `重命名` 或 `删除`。

## Goals / Non-Goals

**Goals:**

- 让当前 Vault 文件树的右键菜单项与用户给定的 Obsidian 参考一致。
- 将文件与文件夹的拖拽入口改为整行，并在拖拽全程提供稳定、清晰的视觉反馈。
- 将文件夹整行点击语义调整为“定位 + 展开/收起”，降低窄箭头目标带来的操作成本。
- 将 Vault 根节点菜单与普通文件夹菜单分离，避免对 Vault 本体执行危险操作。
- 将笔记树的字号、行密度与目录引导线风格对齐到文件系统模块的文件树，强化树状层级可读性。
- 在不引入新的数据模型前提下，为未来真正的“收藏”能力预留稳定入口。

**Non-Goals:**

- 不引入收藏持久化、收藏列表、收藏筛选或任何相关工作台状态。
- 不引入跨 Vault 拖拽、拖拽排序或拖入非文件夹区域的复杂落点规则。
- 不改动笔记面板整体布局、Vault 切换模型或设置面板结构。
- 不追求一比一复刻 Obsidian 全量文件浏览器行为，只对齐本轮确认的核心交互。

## Decisions

### 1. 将文件树右键菜单拆分为四类上下文

文件树右键菜单按上下文拆分为：

- 空白区域菜单
- Vault 根节点菜单
- 普通文件夹菜单
- 文件菜单

其中 Vault 根节点菜单不再复用普通文件夹菜单，而是单独限制为：

- `新建笔记`
- `新建文件夹`
- `复制绝对路径`
- `复制相对路径`
- `在访达中显示`

普通文件夹菜单则扩展为：

- `新建笔记`
- `新建文件夹`
- `复制绝对路径`
- `复制相对路径`
- `收藏`
- `在访达中显示`
- `重命名`
- `删除`

文件菜单收敛为：

- `复制绝对路径`
- `复制相对路径`
- `在访达中显示`
- `重命名`
- `删除`

选择这个方案的原因：

- 这能直接对齐已确认的产品语义，避免继续把 Vault 根节点误当成普通目录。
- 文件的主操作已经由单击承担，右键菜单再保留 `打开` 只会制造重复入口。
- 菜单按上下文显式分层，比在同一套 items 上做临时删减更容易维护。

备选方案：

- 继续让根节点复用文件夹菜单：实现最省，但会暴露错误的危险操作。
- 保留文件菜单里的 `打开`：兼容当前实现，但与新的菜单 contract 冲突。

### 2. `收藏` 作为显式占位项存在，但不接入状态层

本轮 `收藏` 菜单项保留在普通文件夹菜单中，但其行为仅限于占位反馈，不写入 `localStorage`、workbench state 或其他持久化结构，也不改变导航树表现。

推荐做法：

- 将其渲染为可见菜单项
- 触发后给出轻量提示，说明收藏能力暂未启用
- 不创建任何 `favorites` 兼容字段

选择这个方案的原因：

- 用户已经明确要求“先只保留菜单位”，该决定需要在设计层阻止后续实现膨胀。
- 直接回写旧 favorites 模型会把已收敛掉的历史状态重新带回来。

备选方案：

- 直接隐藏 `收藏`：最简单，但不符合本轮确认范围。
- 立即恢复收藏持久化：范围明显超出本次 change。

### 3. 拖拽入口从手柄改为整行，并将视觉反馈拆成“源高亮 + 目标高亮”

文件和文件夹节点改为整行可拖，原先依赖 `GripVertical` 的拖拽手柄移除。拖拽期间至少保留两类反馈：

- 被拖动节点保持高亮并降低不透明度，表明它正处于移动中
- 当前可接收的目标文件夹高亮，且根节点作为目标时也使用同一套高亮语义

选择这个方案的原因：

- 整行拖拽更符合桌面文件树的直觉，也更接近参考图中的交互体感。
- 把“源节点”和“目标节点”分成两套反馈，可以降低拖拽过程中位置判断错误。
- 根节点沿用与文件夹一致的目标高亮语义，能减少额外规则。

备选方案：

- 保留手柄拖拽：实现改动小，但与目标体验背离。
- 只高亮目标，不高亮源：实现较轻，但拖动中的归属感偏弱。

### 4. 文件夹整行点击同时承担定位与展开/收起

文件夹节点的整行点击语义调整为：

- 更新当前选中文件夹
- 若该文件夹当前处于收起状态，则展开
- 若该文件夹当前处于展开状态，则收起

箭头仍可保留为等效的显式展开入口，但不再是唯一入口。整行点击与拖拽共存时，应依赖浏览器原生 drag start 时机和最小移动阈值区分“点击”与“拖动”。

选择这个方案的原因：

- 这是当前已确认的用户输入，且更符合桌面文件树“点击整行即可操作目录”的直觉。
- 整行点击可以显著降低窄箭头目标带来的误点和疲劳。
- 保留“当前选中文件夹”更新，可以继续兼容新建笔记/文件夹依赖当前目录的模型。

备选方案：

- 保持“整行只选中、箭头唯一展开”：与最新确认输入冲突。
- 整行只展开不更新选中文件夹：会破坏当前创建操作依赖的目录上下文。

### 5. 拖拽判定继续沿用“仅允许移动到文件夹”的规则

虽然拖拽入口和视觉反馈会变化，但落点判定继续保持当前收敛范围：

- 只有文件夹节点和 Vault 根节点可作为 drop target
- 文件夹不得被拖入自身或后代目录
- 拖回原父目录视为无效移动

路径更新仍复用现有 rename/path replacement 逻辑，保证当前文档、选中文件夹和展开路径同步更新。

选择这个方案的原因：

- 当前路径同步逻辑已经可复用，不需要为本轮交互打磨引入新的文件系统能力。
- 保持落点规则不变，可以把风险集中在 UI 反馈而不是数据一致性上。

备选方案：

- 一并支持排序或拖入空白区重排：复杂度过高，且不在当前目标内。

### 6. 笔记树的层级视觉语法对齐文件系统树

笔记树的文件和文件夹节点在视觉上应当与文件系统模块保持同一套层级语法：

- 文件和文件夹名称使用与文件系统树一致的紧凑字号与行密度
- 每层缩进使用与文件系统树一致的目录引导线颜色与节奏
- 目录引导线仅用于表达父子层级，不改变现有点击、拖拽和右键菜单判定

同时，目录定位态与当前激活文件态需要区分优先级：

- 当存在当前激活文件时，文件高亮优先展示
- 当前选中文件夹和 Vault 根节点只保留内部状态，不应继续与激活文件同时显示为选中高亮

选择这个方案的原因：

- 用户已经明确要求笔记树在视觉上贴近文件系统树，而不是继续保持偏大的字体和弱层级提示。
- 目录引导线可以直接强化嵌套关系，降低深层目录浏览时的定位成本。
- 将文件高亮设为唯一显式选中态，可以避免当前文件和目录定位态同时高亮带来的歧义。

备选方案：

- 只缩小字号、不增加引导线：实现更轻，但无法解决层级关系辨识偏弱的问题。
- 保留文件夹选中高亮与文件高亮并存：会继续制造双选中错觉。

## Risks / Trade-offs

- [整行可拖后，单击选中与拖拽启动更容易相互干扰] → 使用拖拽阈值和浏览器原生 drag start 时机，避免轻微点击就误触移动。
- [整行点击同时承担展开/收起后，误拖和误折叠更容易相互干扰] → 保持点击与拖拽判定分离，并在实现中优先依赖浏览器 drag 触发条件区分动作。
- [根节点菜单与普通文件夹菜单分离后，菜单构建逻辑会变复杂] → 将菜单生成拆成独立分支，避免在同一数组上做脆弱删减。
- [保留 `收藏` 菜单但不落地功能，可能让用户期待落空] → 用明确提示说明该功能尚未启用，并在 spec 中写死“不产生状态变更”。
- [拖拽高亮如果只靠背景色，深色主题下可能不够醒目] → 同时叠加背景、描边或透明度变化，确保源和目标的层级差异足够清晰。
- [引入目录引导线后，树行内容可能显得拥挤] → 复用文件系统树的间距和字号基线，不额外叠加装饰性元素。
- [隐藏文件夹选中高亮后，用户可能误以为当前目录丢失] → 保留内部 `selectedFolderPath` 状态，只调整其视觉优先级，不影响新建目标目录逻辑。

## Migration Plan

1. 调整笔记文件树的菜单构造逻辑，拆分根节点、普通文件夹、文件和空白区四类菜单。
2. 复用现有复制路径能力，接入到笔记树菜单项。
3. 移除拖拽手柄，将 draggable 能力上移到整行节点，并补齐源节点/目标节点高亮。
4. 将文件夹整行点击语义调整为“更新当前目录并展开/收起”，验证其与拖拽不会互相破坏。
5. 将笔记树字号、行密度与目录引导线对齐到文件系统树，并修正文件与目录定位态的选中视觉优先级。
6. 保持现有 move/rename 路径同步逻辑不变，只验证 UI 交互没有破坏当前路径更新。

本次变更不涉及数据迁移。若需回滚，只需恢复旧的菜单组合和拖拽入口，不会影响 Vault、笔记内容或 workbench state。
