## Context

当前 `MarkdownPreview` 会在 Markdown 文件存在标题时渲染左侧悬浮标题树。组件通过 `outlineExpanded` 控制展开状态，`nav.markdown-heading-outline` 在 hover 或 focus 时展开，内部包含可见的 rail 图标和标题树 panel。

现有实现的问题是：收起状态虽然把父容器宽度设为较窄值，但隐藏的 panel 仍在 flex 布局中参与高度计算。实际鼠标命中区域变成 Markdown 内容左侧一条较高的竖向区域，而不是可见的 24px 左右入口。用户从正文左侧开始拖拽选择文本时容易触发 `onMouseEnter`，导致标题树面板意外弹出并干扰选区操作。

本次变更只调整标题树入口和面板的交互命中区域，不改变标题收集、点击滚动、Markdown 渲染、评论、查找或文件树行为。

## Goals / Non-Goals

**Goals:**

- 收起状态下，鼠标 hover 触发区域 SHALL 仅覆盖可见的标题树入口。
- 展开状态下，鼠标位于可见入口或已展开标题树面板时 SHALL 保持面板展开。
- 保持键盘 focus 展开标题树和标题项可聚焦的可访问性行为。
- 保持标题树浮层不参与 Markdown 正文排版，不改变正文宽度或换行。

**Non-Goals:**

- 不新增用户设置或持久化开关。
- 不改变标题扫描、标题层级展示、标题点击滚动算法。
- 不改变 Markdown 评论数据、评论面板、查找高亮或 GFM checkbox 写回逻辑。
- 不为代码预览或非 Markdown 文件增加结构导航。

## Decisions

### 决策 1：修正收起态命中区域，而不是只缩小宽度数值

**选择**：让收起态标题树容器的实际 hover 命中区域与可见 rail 入口一致，避免隐藏 panel 或父容器高度形成额外触发区。

**理由**：

- 用户的问题来自“可触发区域过高”，单纯把宽度从 30px 调小只能减少横向误触，不能解决纵向整条热区的问题。
- 可见入口和命中区域一致更符合用户预期：看到哪里，鼠标移到哪里才触发。
- 该方案不需要改变标题树视觉形态或新增复杂交互状态。

**替代方案**：只把收起宽度改成 24px 或更小。否决原因是隐藏 panel 仍可能撑高父容器，意外 hover 仍会发生。

### 决策 2：展开 panel 与收起态布局解耦

**选择**：调整标题树 panel 的定位或 pointer-events 规则，使其在收起态不参与鼠标命中；展开态才允许 panel 接收鼠标事件并保持展开。

**理由**：

- 当前 panel 在视觉上被隐藏，但布局和容器尺寸仍影响 hover 命中，应该让交互模型与视觉状态一致。
- 展开后 panel 仍需要可点击标题项、可滚动、可 hover 保持展开，因此不能简单永久禁用 panel pointer events。
- 将 panel 从收起态命中区域中移除，可以减少与正文选择、评论 selection toolbar 的冲突。

**替代方案**：在 `onMouseEnter` 中增加选中文本检测，正在选择文本时不展开。否决原因是这只能覆盖拖拽选区场景，不能解决普通鼠标移动误触；而且会引入与 Selection API 时序相关的边界问题。

### 决策 3：保留 focus 驱动的展开行为

**选择**：继续允许标题树入口获得键盘 focus 后展开，并在失焦到标题树外部时收起。

**理由**：

- 现有 spec 已要求 hover 或 focus 展开标题树，修复鼠标误触不应削弱键盘可访问性。
- 标题项在展开后仍应可通过键盘聚焦和触发。
- focus 行为由真实 DOM focus 状态驱动，和鼠标命中区域收窄可以相互独立。

**替代方案**：只保留鼠标 hover 展开，移除 focus 展开。否决原因是不符合现有可访问性要求。

## Risks / Trade-offs

- [Risk] 收起态命中区域过小，用户更难发现入口 → Mitigation: 保持 rail 图标尺寸和视觉位置稳定，只收窄隐藏 panel 造成的额外区域。
- [Risk] panel 改为脱离布局后，展开位置或最大宽度在窄预览区发生溢出 → Mitigation: 继续使用现有 `max-width` / `max-height` 约束，并在实现时检查窄宽度下 panel 不遮挡关键控件。
- [Risk] 鼠标从 rail 移到 panel 的过程中短暂离开父容器导致闪烁 → Mitigation: 让展开态容器覆盖 rail 与 panel 的可见区域，或用 CSS 定位确保二者之间没有不可 hover 的断点。
- [Risk] focus/blur 逻辑与 pointer-events 调整发生冲突 → Mitigation: 保持 `focus-within` 或等效焦点判定，确保标题项获得焦点时面板不会收起。
