## Why

当前笔记模块存在两个直接影响可用性的缺口：编辑器没有将 `- [ ]` / `- [x]` 渲染为可见的任务列表 checkbox，导致 GFM 任务列表在笔记工作流中不可用；同时笔记面板在编辑过程中会吞掉 `Command + O`，用户无法像浏览器面板那样随时切换面板显隐。两个问题都与现有规格预期不一致，且都会打断高频记录流程，需要尽快补齐。

## What Changes

- 明确笔记编辑器必须把 GFM 任务列表语法渲染为可见的 checkbox 样式，并在加载已有内容与持续编辑过程中保持一致表现。
- 明确 `Command + O` 是笔记面板的保留开关键，无论焦点位于笔记编辑器还是笔记面板内搜索输入框，都必须继续触发面板显示/隐藏。
- 对齐笔记面板与浏览器面板的 overlay 开关交互，确保保留开关键不会被内部输入组件拦截。

## Capabilities

### New Capabilities

无

### Modified Capabilities

- `note-editor`: 补充 GFM 任务列表在所见即所得编辑器中的可见渲染要求，明确 checkbox 样式必须在加载和编辑时出现。
- `note-panel`: 补充笔记面板在内部编辑器或搜索框获焦时仍可通过 `Command + O` 切换显隐的要求。
- `keyboard-shortcuts`: 补充笔记面板快捷键的保留行为，明确其优先级与浏览器面板 `Command + L` 一致。

## Impact

- 影响笔记编辑器的 Vditor 配置、任务列表节点渲染与相关样式。
- 影响应用级快捷键分发逻辑，以及笔记面板内部输入控件对 `Command + O` 的事件处理。
- 影响笔记面板与其他 overlay 的交互一致性验证。
