## Context

当前笔记编辑器将切换为 `Vditor`，并继续承担所见即所得 Markdown 编辑职责。任务列表 checkbox 的问题不再通过修补原有 `Milkdown` 渲染链路处理，而是通过 `Vditor` 原生支持的 GFM 任务列表渲染能力解决，同时保留当前笔记面板的 autosave 与内容回调接口。

快捷键层面，通用快捷键注册位于 `ShortcutContext.tsx`，其主监听器会在 `isEditableTarget(event.target)` 为真时直接返回，因此当焦点落在笔记编辑器或笔记面板内部搜索输入框时，`toggle-notes` 不会触发。浏览器面板已经在 `App.tsx` 中通过捕获阶段的专用 `keydown` 监听器把 `Meta+L` 作为保留开关键处理，这为笔记面板提供了直接可复用的模式。

## Goals / Non-Goals

**Goals:**

- 让 GFM 任务列表在笔记编辑器中以可见 checkbox 样式呈现，覆盖加载已有内容和持续编辑两个阶段。
- 让 `Command + O` 成为笔记面板的保留开关键，在笔记编辑器、面板搜索框获焦时依然可以切换显隐。
- 保持笔记面板与浏览器面板的 overlay 行为一致，不引入新的快捷键体系。

**Non-Goals:**

- 不新增任务列表点击写回、批量勾选或其他超出本次问题描述的编辑能力。
- 不改变笔记面板的布局、动画、互斥规则或 autosave 机制。
- 不为其他输入区域补做额外兼容策略，除非它们直接影响本次笔记面板保留开关键行为。

## Decisions

### 决策 1：改用 Vditor 承载笔记编辑器，而不是继续修补 Milkdown 链路

**选择**：将笔记编辑器从 `Milkdown` 切换为 `Vditor`，使用其原生 Markdown 编辑与任务列表渲染能力，并保持当前 `content / fileKey / onContentChange / autoFocus` 接口不变。

**理由**：

- 用户已明确确认接受编辑器方案切换，问题不再局限于单点渲染缺陷，而是整体编辑体验不满足预期。
- `Vditor` 对标准 Markdown 与 GFM 任务列表的支持更直接，能减少自定义渲染链路和样式补丁。
- 保留现有面板集成接口，可以把影响面控制在 `NoteEditor` 及其样式层。

**替代方案**：继续修复 `Milkdown` / `Crepe`，或退回纯文本 textarea + 预览层。否决原因是前者已经多次尝试仍未达到预期体验，后者则会改变当前的编辑模型。

### 决策 2：将笔记面板展示/收起动作的当前绑定提升为捕获阶段保留开关键

**选择**：参考浏览器面板的实现，在 `App.tsx` 为 `toggle-notes` 当前绑定增加专用捕获阶段监听器。默认绑定仍是 `Meta+O`，但若用户修改了笔记面板快捷键，保留开关键行为也 SHALL 跟随新的绑定值。

**理由**：

- 通用快捷键监听器会跳过可编辑目标，无法满足“输入过程中仍可切换”的要求。
- 捕获阶段处理可以在编辑器和输入框消费按键之前保留当前笔记面板绑定的优先级。
- 与浏览器面板保留开关键使用同一模式，行为更一致，维护成本更低。
- 跟随当前绑定值可以保持与现有快捷键配置持久化能力一致，不制造“设置里改了但输入态仍旧只认旧快捷键”的割裂体验。

**替代方案**：只修改 `ShortcutContext` 的 `isEditableTarget` 例外名单。否决原因是会把 overlay 保留开关逻辑耦合到全局通用监听器里，后续很难表达“仅某些动作可穿透输入控件”的差异。

### 决策 3：将保留快捷键行为限定在笔记面板上下文，而不是放宽所有编辑器按键拦截

**选择**：仅保证笔记面板展示/收起动作的当前绑定在笔记面板打开时可关闭、关闭时可打开；其余编辑快捷键仍由编辑器或输入框自身处理，不扩散为“所有应用级快捷键都能穿透输入态”。

**理由**：

- 本次用户诉求只针对笔记面板开关，不需要扩大键盘模型的影响面。
- 避免意外破坏编辑器中的标准快捷键语义，例如文本选择、撤销重做或搜索输入。
- 更容易为规格和测试建立清晰边界。

**替代方案**：统一让所有 overlay 开关都绕过输入态。否决原因是会改变现有快捷键优先级，风险超出本次变更范围。

## Risks / Trade-offs

- [Vditor 样式与应用主题需要重新对齐] → 通过在笔记编辑器容器下重映射主题变量，并限制样式作用域降低外溢风险。
- [捕获阶段监听与现有通用快捷键重复触发] → 在保留开关键命中后统一 `preventDefault + stopPropagation`，避免后续冒泡阶段再次触发注册动作。
- [面板关闭时焦点残留导致后续键盘行为异常] → 复用当前 overlay 切换后的 blur 逻辑，确保隐藏笔记面板后焦点回到工作区。

## Migration Plan

该变更仅涉及前端渲染与快捷键分发，无需数据迁移。发布后直接生效；若需要回滚，可整体回退本次前端改动，不影响用户已有笔记内容。

## Open Questions

无。当前问题边界明确，现有实现也已经提供浏览器面板作为对照方案。
