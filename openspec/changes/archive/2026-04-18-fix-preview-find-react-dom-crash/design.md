## Context

当前文件预览查找由 `FilePreviewPanel` 统一维护查询词、当前匹配项和查找框状态，`MarkdownPreview` 与 `CodePreview` 在渲染后通过 `useEffect` 调用 `src/utils/preview-find.ts` 扫描容器文本节点，并直接对真实 DOM 做拆分、包裹和还原。这种实现绕过了 React 的协调过程；当用户在查找框中快速输入、连续切换匹配项时，React 提交更新与手动 DOM 改写会互相干扰，最终触发 `NotFoundError` 并使内容区渲染失败。

这个问题横跨查找状态容器、Markdown 渲染、代码渲染和公共高亮工具，属于跨模块稳定性缺陷。约束也很明确：保留现有 `Command + F` 入口、查找框 UI、结果计数和导航行为，不引入新的依赖，也不增加兼容性分支。

## Goals / Non-Goals

**Goals:**

- 消除文件预览查找对 React 管理 DOM 的直接改写，避免预览查找触发渲染崩溃
- 保持 Markdown 预览和代码预览的现有查找交互不变，包括高亮、当前项、导航和滚动定位
- 让连续输入、快速导航等高频操作成为稳定路径，而不是偶发崩溃路径

**Non-Goals:**

- 不重新设计文件预览查找快捷键或浏览器面板快捷键
- 不新增正则、大小写敏感、整词匹配等高级搜索模式
- 不调整 Markdown checkbox 写回、代码高亮主题或文件树搜索能力

## Decisions

### 决策 1：禁止在预览查找中直接改写 React 管理的真实 DOM

选择：移除当前基于 `TreeWalker`、`replaceChild`、`insertBefore` 的后处理高亮方式，改为在 React 渲染链路中生成高亮结果。

理由：当前崩溃的根因不是匹配算法本身，而是高亮逻辑越过 React 去修改已挂载节点，破坏了协调器对节点父子关系的假设。只要继续保留这种模式，快速输入场景下就仍会有渲染树被破坏的风险。

替代方案：继续沿用 DOM 扫描，但增加节流、异常捕获或更谨慎的节点过滤。该方案只能降低复现概率，不能消除“React 与外部 DOM 改写并发冲突”这一根因，因此不采用。

### 决策 2：将匹配计算收敛为纯数据结果，再由不同预览组件各自渲染

选择：公共层只负责基于原始文本和查询词生成匹配范围、当前匹配索引等纯数据结果；`MarkdownPreview` 与 `CodePreview` 分别在各自的渲染流程中消费这些结果并输出高亮节点。

理由：Markdown 与代码预览的渲染管线不同，前者由 `react-markdown` 生成结构化内容，后者由语法高亮组件输出 token/行结构。把公共逻辑限制在“匹配计算”层，可以复用查找状态与计数规则，同时避免再回到脆弱的通用 DOM 扫描方案。

替代方案：在容器层统一对最终 DOM 做高亮。这个方案正是当前问题来源，且无法稳妥处理不同渲染器的节点结构，因此不采用。

### 决策 3：滚动定位保留在 effect 层，但 effect 只读 DOM，不改 DOM

选择：保留“当前匹配项滚动到可视区域”的副作用逻辑，但 effect 只负责查找已渲染的当前高亮节点并调用滚动 API，不再创建、拆分或还原节点。

理由：滚动定位本质上是浏览器副作用，放在 effect 中合理；问题出在 effect 里同时承担了结构性 DOM 变更。将 effect 限制为只读查询和滚动，可以保留现有交互体验，又不破坏 React 渲染边界。

替代方案：连滚动定位也完全移出 effect，全部依赖渲染时机隐式完成。该方案实现上更绕，也不利于保持当前导航体验，因此不采用。

### 决策 4：保持 `FilePreviewPanel` 的查找状态模型不变

选择：继续由 `FilePreviewPanel` 持有查找框开关、查询词、当前匹配项和匹配总数，修复聚焦在预览渲染层与公共查找工具层。

理由：当前问题不是状态模型错误，而是渲染阶段的高亮方式错误。保持容器层状态模型不变，可以缩小修复范围，避免引入新的快捷键、输入聚焦或文件切换回归。

替代方案：重写整个查找状态流。该方案改动面过大，与当前缺陷的最小修复目标不匹配，因此不采用。

## Risks / Trade-offs

- [Risk] Markdown 预览要在不破坏 `react-markdown`、GFM checkbox 和代码块渲染的前提下插入高亮节点，集成复杂度高于当前通用 DOM 工具。→ Mitigation：把“匹配计算”和“渲染集成”分开，先确保稳定性，再在各自渲染器中做最小集成。
- [Risk] 代码预览在保留语法高亮的同时叠加查找高亮，渲染路径会更复杂。→ Mitigation：明确要求代码语法高亮必须保留，查找高亮只能在现有渲染输出上叠加，不得退化为纯文本渲染。
- [Risk] 连续输入时频繁重新计算匹配范围，可能放大大文件查找的开销。→ Mitigation：继续限定查找范围为当前已加载文件，不引入正则等更重模式；必要时只优化纯数据匹配层，而不回退到 DOM 扫描。
